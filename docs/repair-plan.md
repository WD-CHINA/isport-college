## 会话架构约束

本轮保留浏览器直连学苑 `/api/v1` 的协议，因此浏览器仍需读取 Bearer 令牌。Secure 与 SSR payload 隔离属于本轮加固，不能等同于 HttpOnly。若后续要求浏览器 JavaScript 完全不可读取令牌，需要采用同源认证代理并重新设计会话及部署边界。

## 执行结果

上述五阶段已完成，改动保留在当前工作区。

- 认证拆分为会话 store、登录 UI store 与接口编排；当前请求显式绑定 Pinia，旧 401、登录、退出和资料响应均受会话版本或令牌保护。
- 请求层统一 HTTP/业务错误、响应信封、超时和取消；修复 SSR 转发 `Headers` 时丢失鉴权与语言头的问题，同时阻断入站 Cookie/Authorization 向外部接口继承。
- 公开 SSR 不再等待个人资料；正文与推荐独立加载，资源、动态和教师详情正确返回 404；列表和首页复用分类、等级与分页规则。
- 删除未被使用的课程实现、原型模型与未接入功能的操作表单，保留兼容路由与权限门禁；不可用能力使用统一声明和展示组件。
- composable 按业务域归档，本地业务依赖显式导入；分页、品牌色及跨 workspace 规则集中管理。
- E2E 使用独立的学苑协议服务器，取消整体跳过；补齐真实 SSR、登录恢复、会话隔离、媒体及响应式回归。验收同时修复 PDF 素材缺失根对象引用和音频速度控件在 hydration 前接受操作的问题。
- 架构、CI 和仓库指南已同步到实际实现，生产应用没有新增同源业务 mock。

## 后续能力边界

当前学苑前台协议未提供角色权限、管理端、投稿、积分、教师资料及灵跃业务接口，相关功能维持明确的不可用状态。后续接入应先提供真实协议与后端授权，再补充适配和回归；本轮没有实现这些后端能力。

HttpOnly 会话需要后续同源认证代理设计，保留上文所述架构约束。
